# 设计与可复现执行

## 研究协议

先定义研究单位、来源、处理／暴露、对照、指标、允许修改项、预算和判定规则。记录输入版本、代码版本、环境、配置、命令和输出。

| 类型 | 执行前重点 |
|---|---|
| 机器学习／计算 | 按人／设备／时间等独立单位拆分；基线同数据同预算；预处理只在训练集拟合；验证集选模，测试集最终评估；固定评分程序 |
| 观察性／社科实证 | 目标估计量、混杂路径、识别假设、时间关系、选择偏倚；按设计选匹配、面板、IV、DiD 等，不按显著性选方法 |
| 实验／湿实验 | 区分生物与技术重复；随机化、盲法、批次和独立单位；记录试剂、设备、校准及实际偏离；真实操作按授权与规程 |
| 仿真／工程 | 量纲、边界条件、收敛、网格／步长敏感性、守恒；与解析特例或参考实现比较 |
| 理论／数学 | 明确前提，逐步推导并查反例与边界；数值例子不算证明；证明助手只报告实际验证范围 |
| 定性／混合 | 抽样、访谈／编码、反身性、负案例；没有真实访谈或独立编码者不编引语和一致性分数 |

样本量从最小有意义效应、精度要求、设计结构和资源评估，给出假设及敏感性范围；不用“常见论文 n”直接定数。

## 实现与复现

先查项目环境，复用已有依赖锁定和执行入口。小规模 smoke test 后再正式运行；需加速先查真实硬件／后端，不默认 CUDA。
复现时分别列论文设置、代码实际设置、环境偏差。失败也保留日志，不换数据或指标后称复现成功。

每次运行保留以下信息，字段值要来自真实执行：

```json
{"run_id":"run-001","hypothesis":"待验证机制","status":"planned","data_version":"版本或哈希","code_version":"提交或哈希","command":"真实命令","environment":"环境文件路径","config":"配置路径","seed":null,"metrics":{},"artifacts":[],"deviations":[],"decision":"待运行"}
```

只有实际完成、输出可读且指标可核对才用 `completed`；其他用 `failed`／`cancelled`／`planned`。随机种子不适用用 null 并解释。没有 Git 就存脚本和输入哈希，不造提交号。

## 有限自动迭代

1. 用户已要求优化时，定义可改文件／参数、主指标方向、次级约束、最大次数、每次超时、总时限／费用、最小改善阈值。预算缺失先完成基线方案，取得执行所需预算。
2. 验证数据和评分程序固定，只改允许区域，同评价协议比较，所有种子结果保留。
3. 一次改一个可解释假设，组合变化明确记录。保存候选、分数、耗时、失败原因；程序失败与科研负结果分开。
4. 独立目录或工作树比较，保留可复核基线，不用破坏性重置清理用户变更，未经评估不覆盖最佳模型。
5. 达预算、重复故障、指标异常、数据泄漏、无改善或需要新授权时停止并交付结果。不能延伸为任务外后台调度。
6. 最终候选按目的做重复运行／外部验证／消融后判断稳健性；一次升分只支持该次观察。


## 自动研究适用性先判定

用户需要实验结果时，先检查真实数据、可执行基线、硬件／远程环境和可客观计算的指标是否齐备，再进入实验；不能用写作或头脑风暴代替缺失结果。
训练优化只适用于确有训练目标的任务；其他计算任务定义各自执行与评价接口。
远程 GPU 只有连接、权限、环境和预算真实可用才纳入执行；存在服务器说明不等于当前已能访问。本地无卡时评估小规模可行路径或交付运行方案，不承诺同样性能。


## 专业工具适配

只接入当前任务需要的工具，先核对入口类型、实际路径、支持宿主、版本与依赖。保留最小适配说明：输入格式与单位 → 执行命令／接口 → 输出文件 → 成功判据 → 常见失败与资源限制。
先用代表性样本验证，记录模型／工具版本、输入、耗时、可得费用和验收缺口；未知费用写未知。换重要版本或环境后重测。工具交接明确各自产物，避免重复改稿和重复计算。
重试前列本次新增信息和具体改变；无新信息的重复失败应停止或改路线。保留失败的适用条件；不能将所有失败都写成全局禁令。
